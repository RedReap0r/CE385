รายละเอียด Workshop
Workshop 1: บัตรแนะนำตัว (Variables & Template Literals)
เป้าหมาย: ทำความเข้าใจการประกาศตัวแปรและการประกอบร่างข้อความ

สิ่งที่ทำ: สร้างบัตรแนะนำตัวโดยแสดงข้อมูลส่วนตัว (ชื่อ, รหัสนักศึกษา, อายุ ฯลฯ)

จุดเด่น: เลิกใช้เครื่องหมายบวก (+) ในการต่อข้อความ และเปลี่ยนมาใช้ Template Literal (สัญลักษณ์ Backtick `) ร่วมกับ ${} ซึ่งช่วยให้โค้ดอ่านง่ายขึ้นมาก รวมทั้งมีการเขียนสูตรคำนวณปีที่จะจบการศึกษาไว้ในข้อความโดยตรง

Workshop 2: เจาะลึกชนิดข้อมูล (Data Types & typeof)
เป้าหมาย: เข้าใจพฤติกรรมแปลกๆ ของ Data Types ใน JavaScript

สิ่งที่ทำ: ทดลองสร้างตัวแปรทั้ง 6 ชนิด (String, Number, Boolean, Undefined, Null, Array) และตรวจสอบชนิดด้วยคำสั่ง typeof

จุดเด่น: ได้เรียนรู้ข้อควรระวังสำคัญ เช่น typeof null จะได้ค่าเป็น "object" (ซึ่งเป็นบั๊กที่มีมาแต่โบราณของ JS), การใช้วิธี Number.isNaN() เพื่อตรวจสอบค่าที่เป็น NaN อย่างถูกต้อง และเห็นภาพความแตกต่างของการเปรียบเทียบด้วย == กับ ===

Workshop 3: เครื่องคิดเลขเกรด (Score Calculator)
เป้าหมาย: การคำนวณทางคณิตศาสตร์และการจัดการทศนิยม

สิ่งที่ทำ: เขียนโปรแกรมรวมคะแนนของนักศึกษาจากหลายๆ ส่วน (Workshop, การเข้าเรียน, สอบกลางภาค/ปลายภาค) เพื่อหาคะแนนรวมและเปอร์เซ็นต์

จุดเด่น: ฝึกการแยก "ตัวเลขเกณฑ์คงที่" (เช่น คะแนนเต็ม, น้ำหนักคะแนน) ออกมาเก็บเป็นตัวแปร const ด้านบน เพื่อไม่ให้มีตัวเลขปริศนา (Magic Number) ปะปนอยู่ในสูตร และใช้เมธอด .toFixed(2) เพื่อปัดเศษทศนิยมให้สวยงามตอนแสดงผล

Workshop 4: ระบบตัดเกรด (Grading System with if/else)
เป้าหมาย: การใช้เงื่อนไข (Condition) และการตรวจสอบข้อมูล (Validation)

สิ่งที่ทำ: สร้างฟังก์ชันแปลงคะแนนตัวเลขเป็นเกรดตัวอักษร (A ถึง F)

จุดเด่น: ได้เรียนรู้ว่า ต้องเรียงเงื่อนไขจากคะแนนมากไปน้อยเสมอ (เช็คคะแนน 80 ก่อน 50) เพื่อให้ระบบทำงานถูกต้อง และมีการดักจับข้อผิดพลาด (Validation) คืนค่าแจ้งเตือนทันทีหากผู้ใช้กรอกคะแนนติดลบหรือเกิน 100 นอกจากนี้ยังได้ใช้ for...of วนลูปทดสอบการตัดเกรดหลายๆ ค่าพร้อมกันเพื่อประหยัดเวลา

Workshop 5: ระบบสั่งอาหารออนไลน์ (switch...case)
เป้าหมาย: จำลองระบบตะกร้าสินค้าด้วยการเลือกเงื่อนไขแบบ switch

สิ่งที่ทำ: คำนวณราคาบิลค่าอาหารจากรายการออเดอร์ (เมนู, ขนาด, จำนวน) ที่เก็บอยู่ในรูปแบบ Array of Objects

จุดเด่น: ประยุกต์ใช้เทคนิค Fall-through ในคำสั่ง switch เพื่อรวบเมนูอาหารที่มีราคาเท่ากันไว้ในกลุ่มเดียวกัน (ช่วยลดการเขียนโค้ดซ้ำ) และมีการเตรียม default ไว้รองรับเสมอในกรณีที่ลูกค้าสั่งเมนูแปลกๆ ที่ไม่มีในร้าน

Workshop 6: ระบบตรวจสอบสิทธิ์ (Authentication & Authorization)
เป้าหมาย: การรวมทุกทักษะเพื่อสร้างตรรกะระบบเข้าสู่ระบบแบบเสมือนจริง

สิ่งที่ทำ: สร้างฟังก์ชัน Login ที่รับค่า ชื่อผู้ใช้, รหัสผ่าน, สิทธิ์, สถานะบัญชี และอายุ เพื่อตรวจสอบการเข้าใช้งาน

จุดเด่น: ฝึกวิธีคิดแบบตรรกะคอมพิวเตอร์ผ่าน Logical Operators (&&, ||) และจัดลำดับความสำคัญด้านความปลอดภัย โดยระบบจะทำการตรวจรหัสผ่านให้ผ่านก่อนเป็นอันดับแรกสุด หากไม่ผ่านระบบจะปฏิเสธทันทีเพื่อป้องกันการหลุดรอดของข้อมูลอื่นๆ (Information Disclosure)

ส่วนที่ 3: คำตอบคำถามท้ายข้อ

คำถามที่ 1: ทำไมต้องตรวจ username กับ password ก่อนตรวจ role?
ตอบ: เพราะ username/password คือขั้นตอนการ "พิสูจน์ตัวตน" (authentication) ว่าเป็นใคร
ส่วน role คือการ "ตรวจสิทธิ์" (authorization) ว่าคนที่พิสูจน์ตัวตนแล้วทำอะไรได้บ้าง
ถ้ายังไม่รู้ว่าเป็นใครแน่ชัด (ยังไม่ผ่านการตรวจ username/password) ก็ไม่ควรไปดูหรือให้สิทธิ์ตาม
role เลย เพราะระบบยังไม่สามารถเชื่อถือข้อมูลที่ผู้ใช้ส่งมาได้ การตรวจตัวตนก่อนจึงเป็นการปิดประตู
ตั้งแต่ขั้นแรกสุด ป้องกันไม่ให้คนที่ไม่มีสิทธิ์เข้าถึงข้อมูลหรือขั้นตอนถัดไปของระบบได้เลย

คำถามที่ 2: ถ้าย้ายการตรวจ "อายุถึงเกณฑ์" ขึ้นไปเป็นข้อแรก จะเกิดปัญหาอะไร?
ตอบ: จะเป็นปัญหาด้านความปลอดภัย เพราะเท่ากับระบบ "เปิดเผยข้อมูล" (อายุไม่ถึงเกณฑ์) ให้กับ
คนที่ยังไม่ได้พิสูจน์ตัวตนเลยว่าเป็น username/password ที่ถูกต้องหรือไม่ ผู้โจมตี (attacker) ที่สุ่มกรอก
username/password มั่ว ๆ จะสามารถรู้ได้ว่าบัญชีนี้มีอยู่จริงและรู้ข้อมูลอายุของบัญชีนั้น ๆ ซึ่งเป็น
การรั่วไหลข้อมูล (information leakage) โดยที่ยังไม่ผ่านการยืนยันตัวตนเลย หลักการที่ถูกต้องคือ
ต้องตรวจสอบตัวตน (username/password) ให้ผ่านก่อนเสมอ ก่อนจะเปิดเผยหรือประมวลผลข้อมูลอื่นใด
ของบัญชีนั้น เพื่อไม่ให้คนภายนอกได้รู้ข้อมูลใด ๆ เกี่ยวกับบัญชีก่อนที่จะพิสูจน์ตัวตนสำเร็จ
